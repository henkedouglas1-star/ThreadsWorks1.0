# ContentPaysUs beginner-first design standard

Status: proposed implementation standard; feature freeze remains active. No new functionality or backend changes authorized by this document.

## Universal experience

Every app must answer: What can I accomplish? What should I do next? How does this help my business? Use plain-language outcomes, one primary action per screen, progressive disclosure, mobile-first layouts, and explicit loading, empty, error and success states. Reuse authorized project and creator intelligence rather than repeat questions. Let users review and correct context. Never present generated hypotheses as verified demand or promise revenue.

## DemandWorks pilot

Headline: Find out what people need and what you could sell.

| Existing label | Beginner-facing label |
|---|---|
| Buyer Problem Hypothesis Map | Find Problems to Solve |
| Audience Question Inventory | What People Are Asking |
| Demand Opportunity Brief | Find Business Opportunities |
| Customer Discovery Interview Guide | Talk to Potential Customers |
| Audience Validation Survey Builder | Create a Customer Survey |
| Buyer Research Synthesis Report | Understand Your Customers |
| Alternative & Gap Analysis Worksheet | Find What's Missing |
| Automated Live Web Trend Monitor | Discover Trending Demand |

Group existing tools into four steps: Find a problem; Understand your customers; Test your idea; Choose an opportunity. Keep existing tool IDs, prompts, data, routes and access controls. Optional advanced tools remain accessible. Do not imply that the live trend monitor works while it is in development. Handoffs to OfferWorks, ProductWorks and ContentWorks must be verified before advertised as functional.

## Acceptance criteria

- A first-time creator can identify the next action without specialist terminology.
- Every existing tool remains reachable with its original functionality and saved data.
- AI outputs distinguish assumptions, supplied research and verified evidence.
- No new data model, generation endpoint or feature is required for the initial copy/layout pass.
- Test mobile navigation, keyboard accessibility, existing project context, tool selection, generation, persistence and error handling before release.
- Do not merge or deploy during the feature freeze without owner approval.
